- (constraint) [ADOPTED] Platform: web/PWA only, target Chromium-based Android tablet + stylus (e.g. Galaxy Tab + S Pen). No Safari/iPad, no phone form factor. Decided in brief/addendum after native-vs-web PoC comparison (source: brief addendum, PRD FR-14, §5.2).
- (constraint) [ADOPTED] Ink rendering: Pointer Events API (pressure, pointerType:'pen') + Chrome's Delegated Ink Trails for low-latency stroke rendering over a genkouyoushi grid canvas. Requires HTTPS secure context. (source: PRD FR-3, FR-14)
- (constraint) [ADOPTED] Persistence: IndexedDB only, local-only, no backend, no accounts, no sync. Stroke point streams (x,y,normalized pressure) + active width preset stored grid-relative to the cell, not absolute viewport pixels. (source: PRD FR-12)
- (constraint) [ADOPTED] Export/import: single JSON file covering miss tallies, attempt records, session records (not raw ink); import validates schema+version then replaces (not merges) local data. (source: PRD FR-13)
- (constraint) [ADOPTED] Installability: PWA manifest + service worker, installs to home screen, launches without browser chrome, fully functional offline after install (drill, history, export/import). (source: PRD FR-14)
- (constraint) [ADOPTED] No SRS engine: weak-spot selection is a simple per-card cumulative miss tally biasing probabilistic next-prompt selection within session scope — no due dates/intervals/scheduler. (source: PRD FR-6/FR-7, addendum Rejected Alternatives)
- (constraint) [ADOPTED] Content model: 158 cards (46 hiragana + 46 katakana + 66 yoon), each keyed on grapheme+script as a compound identity; same-sound hiragana/katakana pairs and base/yoon never collapse into one card or tally entry. Model must extend cleanly to kanji/vocab later without redesign (SM-5). (source: PRD FR-1, §6)
- (constraint) [ADOPTED] Single developer is sole user and sole builder; no multi-user/auth data model. Hobby-scale — success is felt/qualitative (SM-1/2/4), not a metrics dashboard; explicit counter-metric against optimizing daily-use frequency (SM-C1). (source: PRD §3.2, §6)
- (assumption) No package.json/build tooling exists yet anywhere in the repo; poc-web/index.html is a single vanilla-JS file with no bundler. poc-native (Kotlin/androidx.ink) is dead code from the rejected native path, not a dependency of v1. App-level stack (framework, bundler, TS/JS, PWA tooling) is fully open — greenfield call for this spine.

- (decision) User is a senior backend engineer, frontend novice; explicit priorities for the UI-layer decision: (1) ink-canvas performance/latency must not regress vs the PoC baseline, (2) code cleanliness/conventional structure over cleverness, since the user will personally read/evolve this code later and fears spaghetti. Asked to be given options rather than asked to evaluate frontend trade-offs blind.
- (decision) UI shell framework: Svelte 5 (via @sveltejs/vite-plugin-svelte), chosen over React and no-framework-vanilla. Reasoning shown to user: Svelte compiles to direct DOM updates (no VDOM diff engine that could ever contend with pointer-event timing), and its component model is closer to plain HTML/JS/CSS with compiler-enforced structure — best fit for a frontend novice who explicitly wants to avoid spaghetti and may extend the code solo later. Canvas/ink module stays outside Svelte's reactive tree regardless (see forthcoming AD on paradigm).
- (decision) CONFIRMED by user: paradigm is Ports & Adapters (Hexagonal) with an isolated real-time ink subsystem. Domain (pure TS: card model, weak-spot selection algorithm, session/attempt aggregation, export schema validation) defines Ports (CardRepository[static in-memory], AttemptRepository, SessionRepository, TallyRepository) implemented by Adapters (persistence/idb, ink/canvas+PointerEvents+DelegatedInkTrails, ui/svelte, io/json-export-import). Adapters depend inward on domain+ports, never on each other. Ink adapter owns its canvas DOM node directly (attaches its own pointer listeners outside Svelte's compiled update code) and calls back into the UI only once per completed stroke — this is the mechanism protecting ink latency from framework overhead.
- (decision) TypeScript (strict mode) adopted across the whole app, no exceptions — fits user's backend/typed-language background, and typing pays off most exactly at the domain/port boundary. Not raised as a question since low-risk/high-confidence default; user free to object.
- (decision) Service worker update strategy: vite-plugin-pwa registerType 'autoUpdate' (silent background update, applied on next load) rather than a prompt-to-reload UI. Simplest option, no extra UI/state needed, acceptable for a single-user hobby app with no multi-tenant staleness risk. Proposed as default alongside TS choice; not objected to.
- (decision) Card content (158 cards) treated as static, build-time reference data (a TS/JSON module compiled into the bundle), not an IndexedDB store — content never changes at runtime in v1, so CardRepository port is backed by an in-memory adapter, not a persistence adapter. Simplifies away seed/migration logic an IndexedDB-backed catalog would otherwise need.
- (decision) CONFIRMED by user: production build hosted on a free static host, GitHub Pages as the concrete default (repo has no remote yet; GitHub Pages proposed and not objected to), via a git-push-to-deploy CI flow (GitHub Actions build+deploy on push to main). Gives a stable HTTPS origin (required for Delegated Ink Trails secure context + PWA installability, FR-14) independent of whether the dev machine is running, unlike the PoC's LAN-served setup.
- (decision) IndexedDB schema (via idb): 3 object stores — tallies (key: cardId, field: missCount; FR-6), attempts (key: id/uuid, fields: sessionId FK, cardId FK, timestamp, timeToFirstStrokeMs, totalTimeMs, strokeCount, revealUsed, selfGrade, strokes[] embedded {points:[{x,y,pressure}] grid-relative, widthPreset}; FR-8/FR-12), sessions (key: id/uuid, fields: date, scope, cardsAttempted, accuracy, closureReason; FR-9/FR-10). Card content is NOT a store (see prior static-content decision) — cardId is a natural-key string "grapheme:script" referenced by tallies/attempts, resolved against the static bundle catalog. Attempt.strokes embedded directly (not a separate normalized store) — FR-8's 'links to raw stroke data' is satisfied by direct containment, not a join; a future builder should not normalize this out.
- (decision) Export/import (FR-13) attempt shape excludes the embedded strokes field — export walks attempts and strips ink data before serializing, since FR-13 explicitly scopes raw ink out of export. This is a real divergence point: the persisted Attempt type and the exported AttemptExport type are NOT the same shape, and a naive implementation could leak stroke data into the export file if it just serializes the persisted record directly.
- (decision) No router library — single top-level Svelte state variable (a screen/view enum) switches between the handful of top-level views (scope picker, drill, session summary, history, settings); matches the small fixed screen count and avoids an unneeded dependency.
