# Reconciliation — Design Import

Source: `imports/Kana Practice UX.dc.html` ("Kana Practice — free-recall drill", 10 screen states across the drill loop + surrounding surfaces).

This source is the most faithfully carried-forward of the three — it's the visual mockup the spines were literally distilled from, and the overwhelming majority of tokens, copy, and layout decisions trace back to it 1:1 (colors, radii, button heights, chip variants, history-sparkline ramp, closure chips, import-warning copy — all match near-exactly). The known intentional deviation (Scope-picker ink-width preset moved to Settings-only) is already called out in EXPERIENCE.md's Information Architecture section, so it isn't re-flagged as a gap here.

- Overall screen inventory and IA (First run, Scope picker, Drill loop states A1–A4, Session summary, History, Settings) → EXPERIENCE.md Information Architecture table, 1:1.
- Colors, type families, radii, button min-height (88px), shadow treatment, chip variants → DESIGN.md tokens match the mockup's inline styles almost exactly (e.g. `#c67139` accent, `18px` card radius, `0 12px 32px` shadow).
- Grade button row (Reveal/Missed neutral, Correct primary-filled) → DESIGN.md `button-primary`/`button-neutral` + EXPERIENCE.md Component Patterns.
- Reveal side-by-side "yours" vs "reference" layout, non-grading, required grade after → EXPERIENCE.md Component Patterns "Reveal" row, matches A3 screen exactly.
- Post-grade toast with running miss-tally copy and Undo → EXPERIENCE.md's toast-banner behavior and the "き · hiragana — missed 3 times now, so it'll come round sooner" copy example, verbatim from A4.
- Session summary layout (accuracy hero, time/reveal stat tiles, missed-chip row with running-tally caption) → EXPERIENCE.md Component Patterns (Stat tile, Toast/chip rows) and Voice and Tone.
- History sparkline five-step color ramp with newest bar always accent → DESIGN.md `history-bar` token description matches the mockup's 10-bar gradient (three `grid-guide` tones → accent on the last bar) exactly.
- Idle-closed / whole-scope / manual-closure chip treatment, dimmed accuracy on idle rows → EXPERIENCE.md History row/State Patterns, verbatim match to the mockup's "closed on idle" / "whole scope" chips and dimmed "63%" value.
- First-run pen-check chip + live pressure readout → EXPERIENCE.md State Patterns "Stylus found" row.
- Settings screen (ink-width presets, idle-close pill toggle, export/import with destructive-replace warning) → EXPERIENCE.md Component Patterns and Settings-related State Patterns, including the "Importing replaces everything here" copy verbatim.
- 800×1280 portrait, single-surface, no responsive breakpoints → DESIGN.md Layout & Spacing, exact figures.

## Dropped or altered

- **Reveal-button dimming state (see reconcile-prd.md for the sharper version).** The mockup's A1 "blank" screen shows Reveal active/undimmed while Missed and Correct are dimmed — i.e. the mockup lets you reveal on a genuinely blank cell. EXPERIENCE.md's Component/State Patterns instead dim *all three* buttons including Reveal until ink exists, contradicting the very mockup it was distilled from. This looks like an unintentional drafting slip during distillation rather than a deliberate correction (nothing in the spines explains the change, and it also breaks FR-5 — see reconcile-prd.md). Flag for a fix: either restore the mockup's behavior (Reveal always available once a prompt appears) or, if the all-dimmed behavior is actually wanted, state the rationale explicitly since it changes a real user path (can't-recall-at-all now requires faking a stroke first).
- **Live "3 strokes · 6.2s" readout during writing** (A2 screen, bottom-right corner of the canvas) was dropped from both spines — no equivalent element appears in DESIGN.md's `genkouyoushi-cell` component or EXPERIENCE.md's Component Patterns. Unlike the item above, this drop looks *correct* rather than accidental: PRD FR-8 collects this data but its own note says "No analysis UI beyond FR-11 is scoped for v1," and surfacing live stroke/timing stats mid-write arguably nudges toward the ML/auto-evaluation feel the product explicitly rejects. Noting it as "dropped" for completeness, but it reads as a deliberate (if implicit) resolution in the spines' favor, not an oversight.
- Header's "N / total" position readout is plain text next to the progress bar in the mockup (no chip styling), but EXPERIENCE.md's Component Patterns chip-tag row lists "neutral... for plain position metadata (card position in header)" as if position were shown as a chip. Minor and low-stakes — the actual behavioral spec (paired with progress bar, plain-text count) matches the mockup; it's just an imprecise cross-reference in the chip-tag row's phrasing, worth a small wording fix rather than a functional concern.

## Qualitative ideas at risk

- **"Grade targets sit in the pen hand's reach"** — one of the mockup's four headline design principles (top banner). This is an ergonomic *rationale* for why the grade-button row sits fixed at the bottom of the screen under the canvas — not just a layout fact but a reason ("reachable by the hand already holding the stylus"). The resulting layout is faithfully carried into DESIGN.md/EXPERIENCE.md (grade buttons "always presented as a row... directly under the canvas"), but the *why* — this is a stylus-ergonomics decision, not just a visual convention — isn't stated anywhere in the spines. A future redesign could relayout the grade row without realizing it would break a deliberate reachability decision.
- **"Prompt = romaji + script, never the glyph"** — the mockup states this as an explicit, load-bearing rule (it's literally what makes the drill a recall test rather than a copy exercise). The spines only imply it, via a typography note in DESIGN.md ("Romaji prompts... are set in `{typography.heading}`... never in `{typography.glyph-ink}`") rather than stating it as a standalone functional/experience rule. The letter is preserved but the emphasis — that this is *the* mechanism making the app work as a recall test, not an incidental typography choice — is buried inside a font-usage note.
- **The slight hand-drawn rotation on rendered glyphs** (`transform: rotate(-1.2deg)` on both the drill-loop's revealed ink and the reference glyph) is a small authenticity touch in the mockup — it keeps brushed characters from reading as too-perfect/typeset. Neither DESIGN.md's typography tokens nor its component specs mention any rotation/imperfection treatment for `glyph-ink` rendering. Minor, but worth a call on whether it was a deliberate design flourish worth codifying or just an artifact of the mockup author's hand.
