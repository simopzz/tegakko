- (decision) Delivery platform is web/PWA (not native Android), decided after building/testing both PoCs; web gave better pressure-to-stroke-width control than androidx.ink (from addendum)
- (decision) Target device is Chromium-based Android tablet + stylus only (e.g. Galaxy Tab + S Pen) — phone is not the form factor, and no Safari/iPad support in v1 (from addendum/PRD)
- (decision) Core writing surface is a pressure-sensitive pen canvas rendered over a genkouyoushi grid (traditional Japanese writing-practice grid), using Pointer Events + Chrome Delegated Ink Trails for low-latency stroke rendering (from brief/PRD FR-3)
- (decision) Three stroke width/pressure presets must be available: Subtle, Expressive, Calligraphy (validated in PoC) (from addendum/PRD FR-3)
- (decision) App must be installable to tablet home screen (PWA manifest + service worker), launch without a browser address bar, and run fully offline once installed (from PRD FR-14)
- (decision) Single-user, local-only tool: no accounts, no login, no cloud sync, no sharing, no multi-user data model (from brief/PRD 5.2)
- (decision) Core loop: prompt shown -> user writes card from memory on canvas -> user self-grades correct/incorrect; no automated stroke-order or ML/OCR grading exists (from PRD FR-4)
- (decision) Reveal control: available anytime before self-grade, shows the card's canonical grapheme; does not auto-assign a grade — user still self-grades after revealing (from PRD FR-5)
- (decision) Before starting a session, user picks scope: full kana set (no extra selection needed) or narrower by script (hiragana/katakana) and by base-vs-yoon toggles; no finer per-card selection assumed for v1 (from PRD FR-2)
- (decision) Weak-spot selection is a lightweight per-card miss tally that probabilistically biases which cards appear next — explicitly NOT a full SRS: no due dates, review intervals, or scheduling UI (from PRD FR-6/FR-7, addendum Rejected Alternatives)
- (decision) Session closes on any of: explicit 'I'm done' control tapped, full scope completed, or ~5 min idle timeout (idle-closed sessions are flagged/visually distinguished so they don't skew accuracy trends) (from PRD FR-9)
- (decision) Session history view is reachable from main app navigation, lists past sessions reverse-chronological (date, cards attempted, accuracy%, closure reason), with inactivity-closed sessions visually distinguishable from user-completed ones (from PRD FR-11)
- (decision) Export/import for backup: exports miss tallies, attempt records, session history as one JSON file (not raw stroke/ink data); import defaults to replacing local data outright, not merging (from PRD FR-13)
- (decision) v1 content set totals 158 cards: 46 base hiragana + 46 base katakana + 66 yoon (11 rows x ゃ/ゅ/ょ x 2 scripts); extended katakana loanword combos (e.g. ティ, ファ) are out of scope (from PRD FR-1)
- (decision) No gamification anywhere in UI: explicitly no streaks, points, badges, mnemonics, or daily-use pressure mechanics — this is a standing product boundary, not just a v1 omission (from brief/PRD 5.2)
- (decision) Success is felt/qualitative, not a metrics dashboard: primary success is a fast honest recall check (SM-1) and history showing accuracy holding/improving (SM-2); ink feel being 'satisfying enough to want to reach for it' is an explicit success criterion (SM-4); daily-use frequency/session count is an explicit counter-metric to NOT optimize for (from PRD §6)
- (assumption) Use context (UJ-1): the creator opens the app mid-day, on the spot, when unsure about a single character, and expects the full prompt-write-grade loop to complete in under a minute — implies a fast, low-friction entry into a single drill, not a heavyweight setup flow (from PRD)
- (assumption) Use context (UJ-2): days into use, the creator opens session history specifically to check whether accuracy is trending up or flat — history view should make trend legible at a glance, not just list raw records (from PRD)
- (event) No visual/brand direction (colors, typography, mood) is stated anywhere in brief/addendum/PRD beyond 'genkouyoushi grid' and 'real ink quality' — DESIGN.md starts from a blank slate on visual identity, must be invented fresh
- (event) Parked ideas NOT to design for in v1 (v2+, not decided): exportable image/notebook-diary-page artifact of a day's writing; ink-blot-fades-if-you-quit abandon-session mechanic (would need to avoid becoming a disguised streak mechanic) (from addendum Parked Ideas)
- (event) Parked ideas NOT in v1 UX scope: KanjiVG stroke-order dataset and radical-based character grouping — both only relevant once kanji is introduced (v2+) (from addendum Parked Ideas)
- (decision) Each attempt record captures: card (grapheme+script), timestamp, time-to-first-stroke, total time to self-grade, stroke count, whether reveal was used, self-grade result, plus a link to raw stroke ink data — but no analysis UI beyond session history is scoped for v1 (from PRD FR-8)
- (assumption) Ink latency/feel NFR: must match or exceed the validated web PoC's felt quality on the same device class, judged qualitatively via direct side-by-side comparison, not a numeric threshold — reinforces that ink rendering fidelity (pressure-to-width response) is a top design-quality bar, not just a technical checkbox (from PRD FR-3 NFR)
